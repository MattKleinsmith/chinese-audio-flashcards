# 听力卡 · Listening Cards

Listening flashcards for Chinese. The **front** of each card is a clip of a **native speaker**
(no TTS). The **back** shows the characters, pinyin and definition. The clips are single words
or short sentences, built from the vocabulary you already know from Hack Chinese, so you can do
a few reps while waiting in line.

**Live app:** https://mattkleinsmith.github.io/chinese-audio-flashcards/

- A static PWA with no server and no account. All progress lives in your browser (IndexedDB).
- The audio can be replayed, but the app never shows a clip's duration, a seek bar or a waveform.
  That way you cannot learn "the 1.3 s one is 图书馆".
- Scheduling is SM-2 with learning steps, graded Again / Hard / Good / Easy.
- Once installed it works offline for cards you have already played.

## Using it

1. **Import your vocab**: in Hack Chinese open a list → *List Options* (⋮) → *Export*, then in
   the app go to *Import* → *Choose files…*. Any CSV/TSV/TXT works: columns are detected
   automatically, and you can fix the mapping in the preview. Imports add up across files,
   and importing the same file again changes nothing.
   No export? Use **Quick start with HSK levels**.
2. **Study**: choose *Words*, *Sentences* or *Mixed*. The clip plays automatically. The big
   button pauses and resumes; the row under it restarts the clip or jumps back 5 s, 1 s, 0.5 s
   or 0.1 s (tap repeatedly for fine control); the chips set the speed from 0.25× to 1.5× with
   the pitch preserved. Tap *Show answer* to see the card, then grade yourself. Keyboard: space
   play/pause, ← back 1 s (shift 5 s, alt 0.1 s), r restart, [ ] slower/faster, 1–4 grade.
3. A sentence card only appears when you know every word in it. In Settings you can allow 1 or
   2 unknown words. Tap any word in a revealed sentence to see its definition, or add it to
   your vocab.
4. **Back up** from Settings → *Export everything*. Everything is stored in this browser only.

On a phone, use *Add to Home Screen* so it runs full-screen. The full manual test script is in
[docs/TESTING.md](docs/TESTING.md).

## GitHub Pages

`.github/workflows/pages.yml` deploys `site/` on every push to `main` (and to the dev branch)
when the Pages source is **GitHub Actions** (Settings → Pages → Build and deployment). If the
source is instead **Deploy from a branch** at the repository root, the root `index.html`
redirects to `site/` and `.nojekyll` stops Jekyll from rewriting anything, so the app works
either way. The Actions deploy also stamps the short git SHA into the service worker and
into Settings → About.

## Development

```sh
npm install            # dev-only: Playwright (the app itself has no dependencies)
npm run serve          # http://localhost:8080 serving site/ (MIME types + Range support)
npm run serve:fixture  # same, but with the tiny test bundle in tests/fixtures/data
npm test               # unit tests (node:test) + headless e2e smoke test (Playwright)
```

- `site/` is the whole deployable app: vanilla ES modules, no framework, no bundler, no build
  step. `scripts/serve.mjs --data-dir <dir>` serves another data bundle at `/data/`.
- The e2e test uses `site/data` if it exists, otherwise `tests/fixtures/data`
  (`npm run fixture` regenerates the fixture, and needs ffmpeg via `imageio-ffmpeg`). CI
  installs Chromium with `npx playwright install --with-deps chromium`.
- Opening `site/index.html` straight from `file://` is not supported for real use. Browsers
  block ES modules and `fetch` there, so the page shows a hint to use `npm run serve`. The
  service worker only registers over http(s).

Layout:

```
site/            index.html, sw.js, manifest.webmanifest, css/, icons/
site/js/         main.js (router) · db.js (IndexedDB) · data.js · state.js · importer.js
                 scheduler.js · queue.js · audio.js · pinyin.js · util.js · screens/*.js
site/data/       generated audio bundle (manifest.json, words.json, sentences.json, clips/)
pipeline/        Python pipeline that builds site/data (see pipeline/README.md)
tests/unit/      importer, scheduler, pinyin, queue, data-contract tests
tests/e2e/       smoke.mjs (Playwright, 390×844 headless Chromium)
docs/PLAN.md     the full specification
```

## Rebuilding the audio bundle

`site/data/` is generated by the Python pipeline in `pipeline/`: CC-CEDICT + audio-cmn word
clips + AISHELL-3 sentence clips. See [pipeline/README.md](pipeline/README.md) for venv setup,
the exact build command and how to do a larger local build. The app reads the bundle through
the data contract in [docs/PLAN.md §4](docs/PLAN.md). Clip URLs are `manifest.baseUrl` (or
`./data/`) + `clip.file`, so the clips can be moved to another host without code changes.
